Gate

Run non-mutating COMMIT_PREPARE, authorize exact COMMIT, review its expected OID, then present only the bound non-force command for user execution.

Durable approval: remove the one exact superplanner-approval:start/end marker pair and all enclosed bytes from the exact UTF-8 artifact, preserve every outside byte, then record sha256:<64 lowercase hex>. SHA-256 covers non-Git artifact/evidence checksums; repository OIDs use that repository's SHA-1 or SHA-256 format. All five candidate approval fields and external mirrors must match; state alone cannot authorize the next gate.
Git boundary: non-Git work stops after spike, design, or planning, including decomposition. Retained implementation, commits, SHA-bound reviews, and push eligibility require a complete non-shallow Git repository supplied by the user using the files ref backend. Trusted non-Git parsing validates its repository/object/ref-format tuple from immutable config bytes and proves the common-directory shallow path absent. The non-local clone transfers objects, then a trusted non-Git serializer reconstructs the private mirror's exact refs, symrefs, and HEAD from stable source manifests before use. Reftable and invalid, unknown, redirected, or shallow repository state blocks. Superplanner never initializes Git.

Delivery

Isolated writers

All five candidate-file specialists run through a required isolation supervisor in re-rooted, private, process-sandboxed OpenCode instances using a distinct OS security principal or attested kernel-enforced same-principal isolation across filesystem access, process inspection/control, inherited descriptors, and privilege escalation. A credential-isolating inference broker supplies remote-model responses while persisted approvals, custom providers, shell, and sensitive external paths remain denied; the coordinator packages integration-bound results into external Git storage.

03 / Recovery

Detect stalled work without assuming live control.

1
Define evidence

Every dispatch names a stable workflow task ID, captures the supervisor-returned OpenCode session ID, and defines milestones, expected output, and a step or execution budget.

2
Use foreground handoffs

Foreground supervisor invocations cannot be live-polled or stopped unless the supervisor advertises those controls. Canonical status is only complete or blocked.

3
Resume first

Resume with the generated OpenCode session ID, never the stable workflow ID, and one focused next action.

4
Use optional controls deliberately

Only an explicitly capable harness may expose live status, cancellation, and five-to-ten-minute checks.

5
Replace safely

Replace only after invocation end or failure, or supported cancellation confirms inactivity; otherwise escalate.

  1. A harness timeout event becomes a blocked handoff with timeout evidence.
  2. The worker-enforced step or execution budget is exhausted.
  3. The same failed action is reported twice without new evidence.
  4. Two live checks show no progress, only when status capability exists.
  5. Unavailable input, permission, or exclusive state prevents progress.

05 / Release

The approval follows the commit.

COMMIT_PREPARE is non-mutating: it may create external evidence but cannot stage, write a commit object, or update a ref. It presents the exact author and committer dates in <unix-seconds> <+|-HHMM> numeric-timezone form and the expected full repository-format OID, backed by persisted independently routed no-write hash-object -t commit --stdin operation/result evidence.
Authorized COMMIT

Require authorization that itself explicitly names the canonical patch hash, candidate tree, message hash, full base commit, target state, exact author and committer dates in numeric-timezone form, and expected full OID. Detached HEAD blocks authorization. Persist a distinct operation/result manifest for every authorized add, write-tree, commit-tree, and update-ref call. No ref mutation or update-ref may begin until the created full OID equals the authorized expected OID. The update binds GIT_COMMITTER_DATE and both branch and symbolic-worktree HEAD reflog appends byte-match the old/new OIDs, name/email, Unix seconds, numeric timezone, and reason.

>
Standard review

Fresh read-only context verifies the clean commit SHA equals the authorization's expected full OID. Python changes add the Python-specific skill.

>
Kimi adversarial review

Fresh review independently verifies the same SHA equals the authorization's expected full OID. Accepted risks need user evidence and exact SHA/scope, then fresh approval.

>
User-executed push

Superplanner never executes, brokers, retries, observes, or reports it. After both reviews, only a target-bound push-presentation-request-v1 may authorize presentation of the config-isolated, hookless command. The supervisor resolves and rehashes registered verification, documentation, source, authorization, commit, review, request, and destination records; validates their cross-links; captures a clean-worktree snapshot; and creates canonical layout, execution-closure, exact-command, and eligibility records. The environment uses a private-only PATH, matching safe.directory, http.followRedirects=false, no candidate config, and an attested closed executable/helper/loader/library graph. Local-only push-present repeats final checks and sends stored bytes through a trusted output guard the model cannot edit. Separate-principal custody remains active until an atomic same-filesystem rename linearizes presented-path revocation; recovery then idempotently records one-use consumption and explicit cleanup state for the manifest-bound trusted-user-decision release record, which has no execution or outcome field. A dirty worktree or changed OID invalidates eligibility.

Change invalidation: any candidate edit after review returns through verification, docs sync, non-mutating COMMIT_PREPARE, authorization naming the canonical patch hash, candidate tree, message hash, full base commit, target state, exact numeric-timezone author and committer dates, and expected full OID, coordinator COMMIT, and fresh standard review. Risk acceptance never replaces reviewer approval.
